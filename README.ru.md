# Omarchy Plugin Observatory 🔭

[English](README.md)

Экспериментальный исследовательский набор для разработки плагинов Omarchy Quattro: **3 086 исторических записей статического разбора** и **10 310 сохранённых evidence anchors**, дополненный [скиллом для агентов](https://github.com/PavelLizunov/omarchy-plugin-patterns).

> Это записи отчётов, не подтверждённая перепись экосистемы и не рейтинг безопасности. Исходные checkout и каждая процитированная строка **не прошли независимую проверку**. Для этого релиза не измерялись работа плагинов, загрузка CPU или расход батареи.

Текущий артефакт: **`v1.0.1-rc.1`**, кандидат в релиз. [Методология](METHODOLOGY.md) · [Исправления](docs/corrections.md) · [Источники](docs/source-notes.md) · [Обратная связь](CONTRIBUTING.md)

## Обзор экосистемы

По сообщению автора, исходное исследование выполнено с помощью Gemini 3.8 Flash. Публичный экспорт не содержит первоначальных журналов выполнения, реестра получения исходников или независимого заключения супервизора. Этот релиз описывает доступные доказательства и их ограничения, не восстанавливая отсутствующую историю предположениями.

### Исторические метки, не актуальные рекомендации

| Сохранённая метка | Записи | Как её понимать |
|---|---:|---|
| `pass` | 2 052 | Историческая оценка, не доказательство безопасности плагина. |
| `warning` | 800 | Историческая оценка, требующая контекста исходного кода. |
| `broken` | 126 | Не подтверждённое число неработоспособных плагинов: некоторые основания об отсутствующих файлах опровергнуты. |
| `suspicious` | 108 | Не количество привилегированных плагинов и не доказательство злого умысла. |

Числа воспроизводятся по сохранённым меткам, включая исправленные случаи. У каждой записи есть отдельный объект `review`. **Прочитайте связанные исправления, прежде чем полагаться на исторические `verdict` или `proof`.** Опровержение одного основания не создаёт новый runtime-вердикт `pass`.

Отдельное поле `features.privilege` содержит **76 true, 1 569 false и 1 441 unknown (`null`)**. Это исторические типизированные аннотации, не независимо установленное поведение. Отсутствие доказательств не равно false. См. [статистику](release/statistics.json) и [реестр утверждений](data/claims.jsonl).

## Ключевые архитектурные выводы

Ниже — выбранные примеры на конкретных ревизиях, не оценки распространённости. Проверенные файлы, hashes и доступные уведомления о лицензиях перечислены в [sources.jsonl](data/sources.jsonl).

### 1. Привилегии и учётные данные

- [Виджет WireGuard](https://github.com/Liran-shternberg/wg-omarchy/blob/dff8c75eb1f2ed3053720c1de8eaecea8f6d7073/Widget.qml) принимает пароль в собственном UI и передаёт его через stdin в `sudo -S`. Действие инициируется пользователем и ограничено `up/down`; проверенный путь не демонстрирует обход авторизации. Обработка системного пароля в UI плагина всё же расширяет границу доверия. Предпочтительнее системный сервис с ограниченным набором операций и подходящей авторизацией, использующий агент аутентификации сессии, где это поддерживается.
- [Установщик веб-приложений](https://github.com/dgoran/omarchy-webapp-browser/blob/b2d153daa80c22cf6ee007aeeeb8887303f19cf2/bin/omarchy-webapp-browser#L463-L505) создаёт pacman-хук, восстанавливающий системную ссылку на изменяемый пользователем лаунчер. Хук выполняет `/bin/ln`, а не лаунчер от root. Это риск целостности, не доказанное автоматическое исполнение от root. Автор документирует привилегированную установку.
- Правки конфигурации требуют разрешённой области, понятного согласия, валидации, резервного копирования/восстановления и безопасной замены. Одно вхождение `sed -i` не доказывает отсутствия согласия.

D-Bus — транспорт, Polkit управляет авторизацией, системный сервис выполняет операцию. Существующие сервисы, включая NetworkManager и logind, покрывают часть задач. Корпус не устанавливает причины выбора интеграции авторами или отсутствие API платформы как доминирующую причину.

### 2. Планирование и владение ресурсами

- [Двухсекундный таймер медиавиджета](https://github.com/bussdeeAI/at.familienfabrik_omarchy/blob/eccd60bf3d1a02e6ab5fdc969e6fd728d743e043/BarWidget.qml#L81-L95) запрашивает активацию семи процессов `playerctl`. Это объявленная работа, не измеренное количество запусков. Часть результатов используется и в tooltip панели: отделяйте необходимое обновление статуса от опроса деталей, а не выключайте всё при закрытии popup.
- [Сервис управления окнами](https://github.com/cytracon/omarchy-window-controls/blob/19319b30105ec977ee393ff8c0cb4121f5f10732/Service.qml#L308-L319) использует повторяющийся таймер 80 мс с защитой от повторного запуска уже работающих процессов. Фактическая стоимость ресурсов не измерена.
- [Компонент проверки почты](https://github.com/VillainRU/omarchy-thunderbird-mail-checker/blob/563aa9f8394a3e76df5e28b1c495377ace4afe9c/Panel.qml) получает события через Unix-сокет. В нём также есть переподключение и процесс уведомления по событию; пример не доказывает отсутствия процессов или пробуждений во всём плагине.

### 3. Парсинг и время жизни объектов

`try/catch` обрабатывает ошибку разбора, но не ограничивает размер входа, не проверяет схему и не гарантирует корректное восстановление. Ограничивайте вход **до** накопления в неограниченном транспортном буфере, затем проверяйте структуру и диапазоны. Проверка длины уже полученной строки не ограничит предшествующее накопление.

Владение QObject освобождает потомков при уничтожении владельца, но не ограничивает накопление, пока он жив. Долгоживущим плагинам также нужны конечные размеры коллекций, удаление устаревшего и отмена запросов. Закрытый popup не обязательно означает уничтожение владельца.

### 4. Локализация

[Локализованные копии встроенных плагинов существуют](https://github.com/robertlindomar/omarchy-ptbr-power/blob/ee037fc056cf22c2b3108afd3623a52c7afb6881/README.md). Общий процесс перевода может уменьшить работу по синхронизации, но исследование не измеряло частоту форков, объём изменений только ради перевода или пропущенные исправления. Форк — допустимый способ кастомизации. [Существующую работу сообщества](https://github.com/omacom/omarchy/issues/7284) стоит учитывать и проверять применительно к конкретной версии.

## Локальный просмотр сводки

Статический просмотрщик показывает сводные числа, текст о методологии и ссылки на данные. Это не поисковый интерфейс по каждому плагину. У него нет сторонних runtime-зависимостей и трекинга.

```bash
# На своём компьютере из корня репозитория; остановка — Ctrl+C.
python3 -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8000/site/` в браузере того же компьютера. EN/RU — редакционные основы; остальные локали являются машинными переводами, требующими языковой проверки. Не открывайте произвольный рабочий каталог для публичного доступа.

## Скилл для агентов: omarchy-plugin-patterns

[Отдельный скилл](https://github.com/PavelLizunov/omarchy-plugin-patterns) — нормативный источник. Идентичная [вложенная копия из шести документов](skill/omarchy-plugin-patterns/SKILL.md) поддерживает offline-использование; старые пути `ai/packs/` — совместимые ссылки, не конкурирующие инструкции.

Качественная **Static review reference matrix** помогает исследовать текущий код, фиксируя защиты, риски и unknown. Это не бенчмарк, процентиль или сертификат. Скиллу не нужны native-библиотеки, загрузка датасета или внешний навык. Зависимости создаваемого плагина — отдельный вопрос.

```bash
# Перед установкой проверьте существующий каталог; не перезаписывайте свои правки.
git clone https://github.com/PavelLizunov/omarchy-plugin-patterns.git \
  "$HOME/.config/opencode/skills/omarchy-plugin-patterns"
```

Проверьте фактическую загрузку скилла клиентом. Структура файлов сама по себе не подтверждает обнаружение OpenCode/Claude или runtime-совместимость плагина.

## Автономная проверка

```bash
python3 tools/verify_public_export.py           # структура, связи, числа, состав и hashes; stdlib
python3 tools/verify_public_export.py --schema  # дополнительно все шесть JSON Schema
python3 tools/rebuild_release.py --check        # детерминированность производных файлов
```

Реестр контрольных сумм и все шесть схем обязательны. Невалидный JSON, повторные ID, сломанные связи владения и небезопасные пути приводят к отказу проверки. `--schema` требует явно описанный пакет `jsonschema` и не выдаёт PASS при его отсутствии. Поиск приватных путей — ограниченная гигиеническая проверка, **не** универсальный сканер секретов. Ни один режим не получает upstream-исходники и не подтверждает исторические интерпретации.

Настройка, тесты и пересборка после изменений описаны в [tools/README.md](tools/README.md).
