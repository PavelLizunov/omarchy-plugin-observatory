# Анонс для X — RU, длинный пост

Черновик для публикации после обновления обоих репозиториев. Упоминание Gemini и рассказ о работе — со слов автора. Число 3 086 соответствует сохранённым отчётам; оно не подтверждает независимую проверку такого числа уникальных репозиториев. Определение подсчёта и источники примеров: [README](../README.ru.md), [методология](../METHODOLOGY.md) и [source notes](../docs/source-notes.md).

---

Сделал Omarchy Plugin Patterns — скилл, с которым можно писать и проверять плагины Omarchy вместе с AI-агентом. Разборы, на которых основаны рекомендации, собрал в Omarchy Plugin Observatory: там можно посмотреть, как другие решают похожие задачи, и перейти к исходникам.

Началось всё с подготовки к собственному плагину для Omarchy. Хотел сначала собрать скилл для агента, поэтому с помощью Gemini 3.8 Flash посмотрел код 3 086 плагинов.

Вот несколько примеров из исследования.

У одного медиавиджета двухсекундный таймер запрашивает запуск семи процессов playerctl. Часть результатов нужна подсказке на панели даже при закрытом окне виджета. Поэтому правило «окно закрыто — остановить все обновления» здесь не учитывает работу самой панели.

В wg-omarchy системный пароль вводится прямо в виджете и передаётся через stdin в sudo -S. Подключение запускает пользователь, но пароль при этом становится доступен коду плагина.

В omarchy-thunderbird-mail-checker компонент получает события через Unix-сокет. В Observatory есть ссылка на эту реализацию — пример обмена событиями между компонентами.

Отдельно заинтересовали переводы. У Omarchy есть локализованные копии плагинов: вместе с переводом приходится поддерживать отдельную копию кода и переносить изменения оригинала. В скилле разобрал, как отделять переводы от логики и вести их в одном репозитории, с учётом возможностей оболочки.
